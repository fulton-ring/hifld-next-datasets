  - **Scope requires an explicit comparison with HIFLD**: the API covers *active* facilities of all administrations (health `vha`, benefits `vba`, cemeteries `nca`, vet centers `vc`), includes mobile facilities with an explicit "latitude/longitude and address could be inaccurate" warning, and drops null fields from responses; the HIFLD layer covered VHA sites (VA hospitals, RRTP, NHCU, outpatient clinics, Vet Centers, VAMC), excluded planned/suspended non-operational sites and mobile clinics, and carried NGA-requested text normalisation. A faithful selection/filter and station-ID mapping must be evaluated before deciding whether the result is a continuation or materially changed product; simply using every API administration is not a valid replacement. ## Verified anonymous first-party route — 2026-11-15

The official [Find VA locations](https://www.va.gov/find-locations/) application was exercised in a browser without signing in, obtaining a developer API key or using a mirror:

1. Enter ZIP `20001` and select the Washington, DC suggestion.
2. Choose **VA health** and **All VA health services**, then **Search**.
3. Inspect the application's own `POST https://api.va.gov/facilities_api/v2/va` response. It returned HTTP **200**, ten rows, and `meta.pagination` containing `currentPage=1`, `nextPage=2`, `totalPages=2`, `totalEntries=20` for the regional search. All ten inspected rows had `lat`/`long` coordinates.

The response preserves IDs such as `vha_688` (Washington VA Medical Center) and string `uniqueId="688"`, plus `facilityType`, `classification`, `lat`, `long`, physical address, `mobile`, `visn`, `operatingStatus`, hours and service information. This demonstrates access to real source records and a candidate station-ID mapping. It does **not** establish parity with the historical layer's fields or IDs, a complete national population, or data freshness for every facility. A `services.health.lastUpdated` value is service metadata, not necessarily a coordinate or facility-record update date.

The production bundle linked by the VA page, `https://prod-va-gov-assets.s3-us-gov-west-1.amazonaws.com/generated/facilities.entry.js`, names the same endpoint and uses a POST search with `type`, `page`, `per_page`, `mobile` and location/bounds parameters. The checked application chooses page size 10 and `mobile=false` for health searches. The captured response's JSON uses camel-case attributes; preserve the actual chosen source representation rather than assume the Lighthouse schema is byte-identical.

This is a normal anonymous application session, **not a credential-free bare HTTP API contract**: a direct GET to the search endpoint returned route-not-found, and a standalone POST without the normal application session returned HTTP 403 `Invalid Authenticity Token`. The successful browser request uses the site's normal session/CSRF handling; no access control was bypassed. Session tokens/cookies were neither published nor committed, and no provider account was created. Only the public URLs, bounded response facts and reproduction flow are recorded here; browser inspection is not a durable full-population capture or independently replayable extraction bundle.

## Complete current-source pipeline — 2026-11-15

The source adapter uses the same normal public session as the VA locator: `HEAD https://api.va.gov/v0/csrf_token` returns HTTP 204 and an anonymous session/CSRF token. The token and cookie stay in memory only; they are never saved in receipts, logs or Git. `POST https://api.va.gov/facilities_api/v2/va` with `type=health` or `type=vet_center`, `mobile=false`, `page` and `per_page=1000` returns complete pagination metadata. No address, radius, location, US-only or bounding-box filter is applied in the runtime pipeline. Session bootstrap is normal application behavior; no developer key, login or bypass is used.

Independent full extractions established 1,308 health facilities and 321 Vet Centers: 1,629 unique original IDs. Two global-box sweeps and a non-spatially-filtered control returned identical complete records; the latter avoids silently omitting missing-coordinate facilities. Every observed record has coordinates; the source includes US territories and longitude 145.729385. The runtime repeats the entire unfiltered population and requires stable full IDs, values, counts and pagination, not just the first page. Pinned count/ID/geometry baselines quarantine changes; altered attributes between sweeps, missing/extra pages, unsupported statuses/types, invalid dates/coordinates and source receipt mismatches also refuse construction. All raw responses and request parameters are retained with original wire/decoded hashes, and replay verifies their complete file roster. HTTP response sizes are bounded; requests are spaced below the producer's 30/minute locator limit.

The complete source is retained raw. Candidate selection excludes exactly native `CLOSED` and `COMING_SOON` statuses (current `vha_568A4` and `vha_623A4`); it retains temporary closures, notices, limited/virtual care and temporary locations without fabricating permanence. The observed candidate therefore has 1,627 features. Benefits and cemeteries are never queried; mobile sites are explicitly excluded by the producer parameter and verified in every response.

The proposed GeoParquet contract preserves every source attribute. Native scalar strings, nulls, booleans and floating-point values remain native, including case/diacritics, `uniqueId` leading zeros, and original `lat`/`long`. Root `id` and `attributes.id` must be identical and are represented once in the `id` column; `source_record_json` retains both original occurrences. Native mixed object/array/null fields (`access`, `address`, `feedback`, `hours`, `operatingStatus`, `operationalHoursSpecialInstructions`, `phone`, `services`) use explicit logical JSON encoding: physical UTF-8 JSON columns carry per-field encoding metadata, and decoding restores original nested types, nulls and missing keys. They are not coerced to a lossy Parquet struct. Full-row readback compares every decoded typed value and the complete source record. WKB points retain the exact source longitude/latitude without reprojection; WGS84 is documented by the [VA Facilities OpenAPI](https://api.va.gov/internal/docs/facilities/v1/openapi.json), including bounding-box semantics and 1,000-record maximum (also verified independently on the public locator).

The current public locator is a maintained VA publication; `services.lastUpdated` is service metadata and is not used as a facility-record, coordinate or release date. Upstream record/coordinate cadence and dated release remain unknown. The twice-monthly polling proposal remains STOPPED. Source authority, compatibility, schema, IDs, baseline, rights and release approval flags remain false. This draft is not an exact reconstruction of the historical NGA/ORNL/TechniGraphics enrichment and does not normalize its text or invent missing historical columns/identifiers. Historical published paths are preserved, and existing independent publication gates apply.

Validation includes source/session, pagination, type/ID/value/null/coordinate/date/filter refusals, duplicate JSON keys, quarantine, wire evidence replay, cache integrity and exhaustive decoded GeoParquet parity. Live Dagster ingest/check/catalog, repeat behavior and approval-refusal results are recorded on PR #895; raw captures, temporary verification scripts, logs and Dagster state stay outside Git.
