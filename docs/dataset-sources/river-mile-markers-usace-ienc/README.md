# River Mile Markers (USACE IENC)

The draft source is the USACE Institute for Water Resources (IWR) — Waterborne Commerce Statistics Center (WCSC) "Navigation Mile Marker" ArcGIS feature service, service layer 0 "River Mile Markers": <https://services7.arcgis.com/n1YM8pTrFmm7L4hs/arcgis/rest/services/usace_river_mile_markers/FeatureServer/0>. The layer reports point geometry, `copyrightText` "U.S. Army Corps of Engineers", and a declared native CRS of EPSG:4269 (NAD83 decimal degrees). The public USACE open-data landing page for the backing item is <https://geospatial-usace.opendata.arcgis.com/datasets/604cdc08fe7d43cb90a0584a0b198875_0>.

## Source identification (verified live 2026-11-12, bounded anonymous probes)

- Producer publication: the public ArcGIS item [`604cdc08fe7d43cb90a0584a0b198875`](https://www.arcgis.com/sharing/rest/content/items/604cdc08fe7d43cb90a0584a0b198875?f=json) "River Mile Markers" (type Feature Service, access public, owner `usace_iwr_cac` on the USACE `services7.arcgis.com/n1YM8pTrFmm7L4hs` ArcGIS Online org) describes the "Navigation Mile Marker dataset" as "over 11,000 waterway milepoints … primarily sourced from the Corps of Engineers Inland Electronic Navigation Charts (IENC) and additionally … the National Oceanic Atmospheric Administration (NOAA), USACE Corps of Engineers Districts (Corps) and other various data sources", and states the dataset "is publicly available without any use restrictions" (item `licenseInfo`). The captured FeatureServer reports that item id as its `serviceItemId`, and the USACE org services directory lists `usace_river_mile_markers` as a FeatureServer.
- Relationship to the delegated USDOT BTS IENC distribution: the [BTS IENC item](https://www.arcgis.com/sharing/rest/content/items/7ec34864c8804468a9cf52d437fe4b6c?f=json) links the chart feature-class directory and master geodatabase, not this WCSC endpoint. It does not establish WCSC delegation or historical product equivalence. WCSC authority is evidenced separately by the producer item, org directory and matching service item ID above.
- Historical HIFLD continuity: the prior 2026-11-12 anonymous request to former HIFLD item `496c6859c35143c69b7458af6049658b` returned `CONT_0001`, “Item does not exist or is inaccessible.” That response cannot distinguish deletion from access restriction. The historical population has not been compared; its recoverability is unknown. No prohibited archive or mirror was fetched for this correction.

## Live-verified pins (2026-11-12)

Count 11,389; complete unique `OBJECTID` roster exactly 1–11389 with roster SHA-256 `251c79ad1bed2abb5cdb3a59a2bf95e4b5f468bc160d40764bbc3cf3922ae456`; declared layer extent `(-124.441335461, 25.95040000000006, 92.12370000000004, 46.70310000000006)` EPSG:4269; nine-field schema (`OBJECTID` OID; `name` integer; `LONGITUDE1`, `LATITUDE1` double; `MILE`, `RIVER_NUMB` nullable integer; `RIVER_CODE`, `RIVER_NAME`, `SOURCE` string); `maxRecordCount` 1000. The exact ID roster, roster digest, and declared extent are pinned fail-closed. The declared extent itself contains sign-flipped Ouachita (OB) source longitudes near +92.12 — observed source values are preserved without repair, and a source-side fix would fail-closed into quarantine for re-pinning rather than being silently ingested.

The service enforces a transfer limit beyond `maxRecordCount`: live probes on 2026-11-12 returned HTTP 404 (text/html) for `objectIds` GET queries of 500+ IDs and HTTP 200 for 250-ID pages, so the module captures the complete layer in 46 bounded 250-ID pages.

## Capture contract

The module captures the complete observed layer in 46 bounded 250-ID pages, retaining every decoded response and wire body with checksummed receipts, before/after count and ID snapshots, and the item/directory/service/layer documents. `capture_validated` (the production entry used by the Dagster ingest asset) validates the USACE item (identity, access, title, and the Navigation Mile Marker / IENC / NOAA description markers), the org services directory entry, and the service document before and after extraction, and enforces the roster-digest and extent pins; it quarantines on any drift. One transient transport failure or incomplete/5xx response per request is retried with bounded attempts, every failed attempt retained as evidence. Default runs capture a fresh source snapshot; an explicit `retained_source_version` config replays a retained capture offline without a currentness claim; retained captures without the distribution-chain receipts are refused.

Candidate outputs: unapproved typed GeoParquet evidence candidate (all nine declared fields in source order/types, `OBJECTID` preserved, nullable source integers preserved, native 2D point WKB in EPSG:4269 with no reprojection or repair), plus a lossless raw GeoJSON capture of the observed layer. Because the copy keeps the native EPSG:4269 coordinates without reprojection, the GeoJSON carries the legacy GeoJSON `crs` member naming `urn:ogc:def:crs:EPSG::4269`; a CRS-free FeatureCollection would be silently read as EPSG:4326 by the catalog's GDAL-based readers.

## Scope and pending decisions

This scope is the complete observed WCSC milepoint product, whose producer describes mixed IENC, NOAA, USACE district and other inputs. Neither the inventory title nor that description proves that every historical HIFLD milepoint or IENC distance mark is present; no row-level containment comparison has been completed. It does not demonstrate equivalence to the archived HIFLD record, the IENC master geodatabase, or the IENC `DISTANCE_MARK_POINT` layer. The HIFLD inventory labels its DataLumos V1 item as modified 2024-12-16; that archive timestamp is not a source edition date, and no immutable producer release date is observable from the service or item. Source edition, HIFLD continuity, schema/ID contract, coverage, rights/attribution, baseline, and release acceptance remain false; the scheduled refresh is stopped and no production publication is implied.


## Source-fidelity recheck (2026-11-15)

Bounded anonymous metadata probes of the producer [WCSC layer](https://services7.arcgis.com/n1YM8pTrFmm7L4hs/arcgis/rest/services/usace_river_mile_markers/FeatureServer/0?f=json), [NDC/LPMS Lock layer](https://services7.arcgis.com/n1YM8pTrFmm7L4hs/ArcGIS/rest/services/Locks/FeatureServer/0?f=json), [IENC distance-mark layer](https://ienccloud.us/arcgis/rest/services/IENC_Feature_Classes/DISTANCE_MARK_POINT/MapServer/10?f=json), and [chart directory](https://ienccloud.us/arcgis/rest/services/IENC_Feature_Classes?f=json) confirmed these product distinctions. This was not a new complete feature capture; counts above remain the dated 2026-11-12 observations.

WCSC reports `editingInfo.dataLastEditDate` 1773157900941 (2026-03-10T15:51:40.941Z). NDC/LPMS reports 1730211610991 (2024-10-29T14:20:10.991Z), while its schema edit is 2025-12-11. Neither metadata document declares an immutable edition or refresh cadence; item modification and schema edits do not establish a newer data release. The BTS IENC description separately specifies partial deliveries on the first and fifteenth business days, occasional special deliveries, and new chart editions or updates. This chart cadence cannot be assigned to WCSC or LPMS, and does not date any captured chart layer.

LPMS describes NDC survey-derived characteristics of USACE built, maintained, owned, or operated locks. Its adapter preserves 48 fields including `NDCCODE`, `LOCKCD`, `CHMBCD`, `NOCHMB`, `STATUS`, dimensions, and binary annotation, with native EPSG:4019. That population is not established as all U.S. locks, one row per chart lock, or the historical HIFLD population. The chart directory separately advertises `LOCK_BASIN_AREA`, `LOCK_GATE_AREA` and `LOCK_GATE_LINE`. No identifier, chamber/site, geometry or population crosswalk between these classes and LPMS has been demonstrated.

WCSC's nine fields include integer `MILE`, river identifiers and `SOURCE` in native EPSG:4269. The separate IENC `DISTANCE_MARK_POINT` has `Waterway_Distance` (double), `Horizontal_Units`, `Category_of_Distance_Mark`, `Feature_ID` and chart provenance fields in EPSG:4326. Its definition includes a structure or distinct location measured from an origin, usually on canals. Matching names or nearby coordinates do not establish record identity. Both adapters query the entire advertised layer (`where=1=1`, followed by explicit ID pages); no IENC-only `SOURCE` filter or historical clipping rule is applied to WCSC.

The shared IENC capture/geometry helpers and the building, crane, pipeline and distance-mark callers were inspected. These callers select exact classes (`BUILDING_SINGLE_POINT` layer 5 in the master service; `CRANES_POINT` layer 8, `PIPE_AREA` layer 82 and `DISTANCE_MARK_POINT` layer 10 in their feature-class services), query their complete advertised populations, and preserve their native geometry. Existing [building](../building-locations-usace-ienc/README.md), [crane](../crane-locations-usace-ienc/README.md), [pipeline](../pipeline-areas-usace-ienc/README.md) and [distance-mark](../distance-marks-usace-ienc-2/README.md) provenance already limits completeness to inland chart layers. Neither shared helpers nor successful paging establish a nationwide building, crane, pipeline or facility inventory. Historical class membership, clipping and population parity remain unverified. This correction changes no source selection, filter, IDs, typed values, geometry, approval flags or stopped schedules.
