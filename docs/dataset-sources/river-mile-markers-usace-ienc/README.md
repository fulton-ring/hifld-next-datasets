# River Mile Markers (USACE IENC)

The draft source is the USACE Institute for Water Resources (IWR) — Waterborne Commerce Statistics Center (WCSC) "Navigation Mile Marker" ArcGIS feature service, service layer 0 "River Mile Markers": <https://services7.arcgis.com/n1YM8pTrFmm7L4hs/arcgis/rest/services/usace_river_mile_markers/FeatureServer/0>. The layer reports point geometry, `copyrightText` "U.S. Army Corps of Engineers", and a declared native CRS of EPSG:4269 (NAD83 decimal degrees). The public USACE open-data landing page for the backing item is <https://geospatial-usace.opendata.arcgis.com/datasets/604cdc08fe7d43cb90a0584a0b198875_0>.

## Source identification (verified live 2026-11-12, bounded anonymous probes)

- Producer publication: the public ArcGIS item [`604cdc08fe7d43cb90a0584a0b198875`](https://www.arcgis.com/sharing/rest/content/items/604cdc08fe7d43cb90a0584a0b198875?f=json) "River Mile Markers" (type Feature Service, access public, owner `usace_iwr_cac` on the USACE `services7.arcgis.com/n1YM8pTrFmm7L4hs` ArcGIS Online org) describes the "Navigation Mile Marker dataset" as "over 11,000 waterway milepoints … primarily sourced from the Corps of Engineers Inland Electronic Navigation Charts (IENC) and additionally … the National Oceanic Atmospheric Administration (NOAA), USACE Corps of Engineers Districts (Corps) and other various data sources", and states the dataset "is publicly available without any use restrictions" (item `licenseInfo`). The captured FeatureServer reports that item id as its `serviceItemId`, and the USACE org services directory lists `usace_river_mile_markers` as a FeatureServer.
- Relationship to the delegated USDOT BTS IENC distribution (registry-approved prefix): the `IENC_Feature_Classes` service directory at ienccloud.us lists 100 services (verified 2026-11-12) and contains **no** river-mile-marker feature class. The BTS IENC delegation item `7ec34864c8804468a9cf52d437fe4b6c` covers the IENC chart products (its distance-mark layer is separately inventoried as `distance-marks-usace-ienc-2`); it does not cover this WCSC milepoint product. This dataset's producer distribution is therefore the USACE IWR WCSC feature service itself — a direct producer publication, not a mirror or archive.
- Historical HIFLD continuity: the former HIFLD-hosted item `496c6859c35143c69b7458af6049658b` ("River Mile Markers (USACE IENC)", inventory source date 2017-06-16) is dead — an anonymous 2026-11-12 request returned ArcGIS `CONT_0001` "Item does not exist or is inaccessible" — and the Wayback Machine holds no usable capture of it. The HIFLD-era population count is therefore unverifiable; historical continuity remains unaccepted. The DataLumos archive item (240621) is a rescue mirror used as research context only.

## Live-verified pins (2026-11-12)

Count 11,389; complete unique `OBJECTID` roster exactly 1–11389 with roster SHA-256 `251c79ad1bed2abb5cdb3a59a2bf95e4b5f468bc160d40764bbc3cf3922ae456`; declared layer extent `(-124.441335461, 25.95040000000006, 92.12370000000004, 46.70310000000006)` EPSG:4269; nine-field schema (`OBJECTID` OID; `name` integer; `LONGITUDE1`, `LATITUDE1` double; `MILE`, `RIVER_NUMB` nullable integer; `RIVER_CODE`, `RIVER_NAME`, `SOURCE` string); `maxRecordCount` 1000. The exact ID roster, roster digest, and declared extent are pinned fail-closed. The declared extent itself contains sign-flipped Ouachita (OB) source longitudes near +92.12 — observed source values are preserved without repair, and a source-side fix would fail-closed into quarantine for re-pinning rather than being silently ingested.

The service enforces a transfer limit beyond `maxRecordCount`: live probes on 2026-11-12 returned HTTP 404 (text/html) for `objectIds` GET queries of 500+ IDs and HTTP 200 for 250-ID pages, so the module captures the complete layer in 46 bounded 250-ID pages.

## Capture contract

The module captures the complete observed layer in 46 bounded 250-ID pages, retaining every decoded response and wire body with checksummed receipts, before/after count and ID snapshots, and the item/directory/service/layer documents. `capture_validated` (the production entry used by the Dagster ingest asset) validates the USACE item (identity, access, title, and the Navigation Mile Marker / IENC / NOAA description markers), the org services directory entry, and the service document before and after extraction, and enforces the roster-digest and extent pins; it quarantines on any drift. One transient transport failure or incomplete/5xx response per request is retried with bounded attempts, every failed attempt retained as evidence. Default runs capture a fresh source snapshot; an explicit `retained_source_version` config replays a retained capture offline without a currentness claim; retained captures without the distribution-chain receipts are refused.

Candidate outputs: unapproved typed GeoParquet evidence candidate (all nine declared fields in source order/types, `OBJECTID` preserved, nullable source integers preserved, native 2D point WKB in EPSG:4269 with no reprojection or repair), plus a lossless raw GeoJSON capture of the observed layer.

## Scope and pending decisions

This scope is the complete observed WCSC milepoint product, which is a mixed-source superset (IENC, NOAA, USACE districts) of the IENC-sourced milepoints named by the HIFLD inventory title. It does not demonstrate equivalence to the archived HIFLD record, the IENC master geodatabase, or the IENC `DISTANCE_MARK_POINT` layer. The HIFLD inventory labels its DataLumos V1 item as modified 2024-12-16; that archive timestamp is not a source edition date, and no immutable producer release date is observable from the service or item. Source edition, HIFLD continuity, schema/ID contract, coverage, rights/attribution, baseline, and release acceptance remain false; the scheduled refresh is stopped and no production publication is implied.
