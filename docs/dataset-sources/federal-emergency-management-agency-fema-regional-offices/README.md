# FEMA Regional Offices — working local draft, release blocked

Issue #83 reconstructs the complete producer-hosted FEMA RegHQs **office point layer0**, not regional polygon boundaries (layer2). The government GIS root lists FEMA, its folder lists `FEMA/RegHQs`, and the service lists layer0 `FEMA Regional Offices` with FEMA copyright; original producer XML is retained. An external ArcGIS account is a discovery pointer only, not an assumed official distributor.

The complete observed layer has **14 offices: 10 regional, 3 area, 1 national headquarters**, native EPSG4326 points and14 original attributes. Count/ID rosters/semantic metadata are checked before and after ID-targeted queries, with exact field declarations, ID coverage, transfer limits, nulls, numeric ranges and geometry validation. No filtering to ten, coordinate geocoding, normalization or ID substitution occurs. Both original SmallInteger attributes stay int16, all source text (including leading-zero ZIPs and the trailing space in `546 Bonney Loop `) stays literal. OID bit width is undeclared; Arrowint64 is a proposed lossless representation rather than an assertion of source storage width. Full source physical declarations stay in sidecars and Arrow field metadata.

The FEMA service returns different random renderer colors between identical data reads. Only `drawingInfo` is excluded from semantic metadata equality/fingerprints. Full unchanged wire metadata remains in raw CAS and the first construction bundle; new observations cannot overwrite original receipts. Changes to any other metadata field during extraction fail closed. All other captured body identities participate in deterministic candidate versions.

All five complete published candidate formats are pinned by SHA256/bytes and provider MD5/generation. Four open formats are decoded completely; PMTiles is preserved and checksummed, with no content/native-fidelity claim. Every open format has14 matching native point geometries. Published GeoJSON retains the source field names/values; Parquet, GeoPackage and Shapefile truncate `region_objectid`/`region_number` to `region_obj`/`region_num`, widen the integers, trim the source address whitespace and add duplicate `id` values. Proposed aliases exist only in diagnostic reports; all published identifiers and original bodies remain separate. No mapping, tolerance or migration is accepted.

The explicit source asset and stopped weekly refresh job stage deterministic native GeoPackage/GeoParquet and complete raw/provenance/lineage evidence. Generic catalog, verification and promotion gates remain authoritative. Complete private outputs and original capture/Git semantics are validated before the shared first-construction CAS/marker/alias is sealed under the common version lock. Unknown/missing/linked cache files or altered source-owned wrappers detach the whole candidate intact. A separately durable negative incident is written **before** detaching any candidate whose original evidence has lost trust; repeated cold refresh cannot rebase original history. Partial incident writes also block. If incident persistence fails, the candidate is preserved. Explicit reviewed operator recovery is required; there is no automatic history repair.

Local capture replay uses `HIFLD_FEMA_OFFICES_CAPTURE_DIR`, otherwise the adapter reads the official endpoint and pinned published candidates. Failed acquisition preserves the complete bounded body before trying receipt access, preserves raw receipt bytes before parsing, and records body-only diagnostics for unreadable receipts. Unsafe storage roots are rejected before acquisition. No production writes are allowed by this draft adapter.
