# Uranium and Vanadium Deposits — parked: no maintained USGS producer publication

Assigned dataset: HIFLD Open *Uranium and Vanadium Deposits* (inventory ID `uranium-and-vanadium-deposits`, Agency U.S. Geological Survey). The DHS HIFLD Open crosswalk (DOI 10.3886/E241367V1) marks the row **Deprecate** and points the retired HIFLD Open item `2c9b52ce91be4384931b64dd551cb6ea` (its services1.arcgis.com FeatureServer answered only ArcGIS "Invalid URL" error documents when probed 2026-11-14) to the producer's **Mineral Resources Data System (MRDS)** publication page.

## Why the dataset is parked (dated evidence)

- **The pointed-to producer publication is frozen.** The live MRDS landing page https://mrdata.usgs.gov/mrds/ (20,610 bytes, SHA-256 `793b6de964e124c11fe915630d59d63a056f4dce05ea577fe9d9ac2d6c4452ac`, observed 2026-11-14) states verbatim: *"Current status: As of 2011, USGS has ceased systematic updates to MRDS, and is working to create a new database, focused primarily on the conterminous US. For locations outside the United States, MRDS remains the best collection of reports that USGS has available. For locations in Alaska, the Alaska Resource Data File remains the most coherent collection of such reports and is in continuing development."* A live download and a newer packaging date do not make the data maintained: the best-available claim is explicitly for locations *outside* the United States, the conterminous-US successor database is still only "working to create", and Alaska is delegated to ARDF. The producer's trim package `https://mrdata.usgs.gov/mrds/mrds-trim.zip` (11,236,725 bytes, SHA-256 `f24f995faaa6f5c66415971b1bb0fa1906273adb37f82c1098266aece47f6a84`, observed 2026-11-14) was fully captured during the superseded draft and validated (304,632 point records; token-exact U/V subset 16,340 records), but a frozen database is not a pipeline input under the current source policy, so the draft reconstruction was removed from this PR.
- **Current producer alternatives checked (2026-11-14):**
  - *USMIN Mineral Deposit Database* (https://mrdata.usgs.gov/deposit/, 40,121 bytes, SHA-256 `49014311524b79db7af267a8e2f0b7cd6a201d7dd46ed3caf6fba5ab990ba502`): self-declared **developing** database — *"A developing national-scale geospatial database that will be an authoritative source of information on the most important mines, mineral deposits, and mineral districts of the United States."* Its published commodity packages (Cobalt, Gallium, Germanium, Graphite, Indium, Lithium, Niobium, REE, Rhenium, Sn, Tantalum, Tellurium, Tungsten) include **no uranium and no vanadium package**, so it cannot recreate this two-commodity layer. The announced USMIN uranium compilation targets deposits with records of significant past production or resources only (GSA abstract, 2022) — a materially different population; vanadium appears only as a by-product companion of uranium in that work.
  - *Alaska Resource Data File (ARDF)* (https://mrdata.usgs.gov/ardf/, 15,022 bytes, SHA-256 `82b4b73adebe5cc8cfe49a8358fe838f0c0c799c7e440a220cb9c9499fadff44`): the producer-designated continuing-development collection, but for **Alaska locations only**; no nationwide coverage.
  - *Earth MRI focus areas* (DOI 10.5066/P9WA7JZY, Dicken and others, 2021; 13 critical minerals including uranium and vanadium): regional focus-area polygons with supplemental tables, **not deposit points**.
  - *Critical mineral deposits of the United States* (ver. 3.0, September 2026, DOI 10.5066/p9k1hbnt): curated **681-deposit** database gleaned from MRDS, ARDF, USMIN and literature for Earth MRI priorities — a materially different and far smaller population than the assigned layer.
- **No mirror or archive was used.** The DataLumos project 240898 (the archived HIFLD Open copy; login-walled, so no byte comparison to the historical layer is possible) is a banned archive source and was never fetched.

## What the parked code does

`src/dagster_hifld/sources/uranium_vanadium_deposits.py` keeps only the pinned producer-contract facts and the fail-closed refusal (`no_maintained_producer_publication_park_or_retire`); it defines no fetching, decoding, staging or candidate output, and every materialization attempt fails closed. The registered ingest asset `ingest/uranium-and-vanadium-deposits/uranium-and-vanadium-deposits` fails closed, job `uranium_vanadium_deposits_parked_refusal` exists for an explicit refusal run, and the monthly schedule `uranium_vanadium_deposits_parked_monthly` is STOPPED. `parse_mrds_status` fails closed if USGS ever changes the MRDS release-status statement, and `parse_usmin_status` fails closed if USMIN ever publishes a uranium or vanadium package or changes its developing scope statement — either event re-opens the source decision explicitly instead of being absorbed silently.

## Resuming requires an explicit maintainer decision

One of: park permanently; retire the dataset; or name a maintained producer source (for example, publication of the USGS conterminous-US successor database named on the MRDS page, or USMIN uranium and vanadium commodity packages covering the assigned population, with a new schema/ID contract). `approved: false` everywhere, no default fetching, no release schedule started, no promotion path introduced.

No production write, schedule start, or release acceptance is implied.
