Draft source: USACE Inland Electronic Navigational Charts `LIGHTS_POINT` ArcGIS layer, service layer 16: <https://ienccloud.us/arcgis/rest/services/IENC_Feature_Classes/LIGHTS_POINT/MapServer/16>. Official distribution is documented by the public USDOT BTS NTAD item [`7ec34864c8804468a9cf52d437fe4b6c`](https://www.arcgis.com/sharing/rest/content/items/7ec34864c8804468a9cf52d437fe4b6c?f=json) (owner `USDOT_BTS`, type PDF, verified live 2026-11-11): its record names the Inland Electronic Navigational Charts program and explicitly links the official `IENC_Feature_Classes` service directory and the `USACE_IENC_Master_Service_gdb.zip` master file geodatabase. Every capture validates this BTS item first (identity, access, and all three delegation markers), then the service directory entry (`IENC_Feature_Classes/LIGHTS_POINT` MapServer) and the service document (`mapName` `LIGHTS_POINT`, `copyrightText` `USACE IENC`, exactly one advertised point layer id 16) before and after extraction, and quarantines on any drift. A prior BTS map-service item (`3607d485a9854d6fa458bf507058ceae`) returned an anonymous-access denial; its catalog succession is recorded but not accepted.

Live-verified pins (2026-11-11, bounded anonymous probes): count 8,892; complete unique `OBJECTID` roster exactly 1–8892 with roster SHA-256 `7c65ad1632fe1735992b7bfb73ecb618137ec9e7be937fb8925bcc7f64e054ce`; declared layer extent `(-96.41382419999997, 29.744945200000075, -79.47503019999994, 45.05656380000005)` EPSG:4326; 21-field schema (20 non-geometry attributes plus `SHAPE`, `Scale_Minimum` integer, three length-20 string fields); `maxRecordCount` 2000. The exact ID roster, roster digest, and declared extent are pinned fail-closed. The earlier draft PR #522 recorded the same population, roster digest, and bounds from its retained 2026-10 capture.

The module captures the complete observed layer in 36 bounded 250-ID pages, retaining every decoded response and wire body with checksummed receipts, before/after count and ID snapshots, and the service/layer documents. It quarantines count, ID, schema, CRS, extent, transfer-limit, or point-ordinate drift, and preserves `OBJECTID` and `Feature_ID` unchanged. Candidate identity binds decoded-body and wire digests while excluding fetch timestamps, so a formatting-only source change yields a distinct candidate and timestamp-only refetches reuse the sealed one. Default runs capture a fresh source snapshot; an explicit `capture_directory` config replays a retained capture offline without a currentness claim.

This scope is the complete observed IENC chart-service layer, whose inland coverage is regional. It does not demonstrate equivalence to the archived HIFLD/DataLumos record, nationwide navigation-light coverage, or the complete IENC master geodatabase. The HIFLD inventory labels its DataLumos V1 item as modified 2025-04-08; that archive timestamp is not an IENC source edition date. Source, schema/ID contract, coverage, rights, and release acceptance remain false; the scheduled refresh is stopped.
