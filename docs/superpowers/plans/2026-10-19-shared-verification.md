# Shared verification implementation plan (proposed)

Date: 2026-10-19. Issue #417. Depends on maintainer review of [the design](../specs/2026-10-19-shared-verification-design.md). This is a reviewable plan only: no design, baseline, schema or release approval is implied. Do not implement from this document until the coordinator records the required design decision.

1. **Approve scope and select independent pilot reference.** Record unresolved choices (SQLite budgets and format-specific comparison rules), a maintainer-approved real accepted HIFLD Next dataset/file/version and explicit inventory/crosswalk/catalog mapping. Pin catalog/dictionary/data object URLs, SHA-256, byte lengths and immutable identities, plus accepted schema/ID/source/criteria evidence. Preserve original baseline. If unavailable, mark real pilot blocked; synthetic fixtures may continue only in the implementation phase and never substitute for it. Do not approve contracts in this PR.
2. **Build typed full-data readers and spill engine.** Extend `validation.py` with versioned request/reference/contract/report dataclasses, streamed Fiona/PyArrow/tabular readers and SQLite BLOB-key indexes. Preserve precise typed values, whitespace and raw fields. Add bounded batches/cache/single-feature limit, enforced disk/RSS budgets, streaming full ID/diff/lineage sidecars and failure reports. Compare exact retained attributes/geometries; full schema/ID/coverage/quality metrics must not reuse sample metrics as acceptance evidence. Test missing/unknown CRS, late-file corruption, oversized rows and quota exhaustion.
3. **Add three-stage receipts and accounting.** Extend optional source-specific extraction receipts and shared verification of all expected partitions/pages/IDs/counts; reject HTTP200 API errors, transfer limits and concurrent mutation. Add transformation contracts/independently checked receipts for union, join, filters, dedup, aggregation, split, geometry construction and output-to-input lineage. No blanket raw/output equality. Exercise all terminal branches and source IDs; grain changes require maintainer compatibility decisions.
4. **Version and propagate provenance.** Extend `source_manifest.py` instead of creating another resolver. Define conflict-detecting multi-input identity/role/date/checksum/rights/transformation/lineage schema; freeze version snapshots. Update dictionary propagation, catalog output metadata and publish metadata allowlist. Update Portolan catalog/STAC/release consumption so readable producers/official links, processor role and downloadable manifests/reports/sidecars survive. Verify roundtrip by reading actual published STAC and downloading its metadata assets, including multi-source and mirror cases. Inventory fallback/research JSON cannot satisfy acceptance.
5. **Integrate initial and final reports.** `assets/catalog.py` writes initial comparison; format generation remains staged. Add final verification asset after every required generated format and build final checksum-bound report covering exact promotable inventory. Use dataset-specific format rules for archives, GeoPackage, GeoParquet, shapefile and derived PMTiles. Unknown/unsupported rules fail closed. Full differences and approval evidence determine outcome; no global percentage or sample pass. Test same-count-ID swaps, geography loss hidden by other growth, extra columns, truncation, missing shards, quality regressions and approved producer changes.
6. **Enforce both gate layers.** Replace legacy hard-coded comparator in `checks/common.py`, use blocking ERROR checks in `checks/__init__.py`, and make promotion depend on final verification. Implement `require_verified_promotion` and integrate every destination-write path: version/source-format/metadata copy, release promotion/write helpers, public Dagster publish, local pipeline and Portolan workflows. Revalidate approvals, destination and complete pinned object inventory at copy boundary; retain conditional immutable copy guarantees. Test forged/stale reports, bytes changed after verification, new shards, publish-only selections and direct helper calls. Preflight before destination writes; expose accepted catalog pointers only after complete success. On failure preserve accepted release/pointer and candidate evidence, including partial-copy retry.
7. **Prove resource behavior and registry correctness.** Run growing subprocess fixtures beyond memory budget with high-cardinality coverage/IDs and full sidecar assertions, measure peak RSS and scratch, and exercise interruption/ENOSPC. Explicitly distinguish supporting assets from terminal outputs in registry wiring; remove first-key assumption only with focused multi-output tests proving all terminal keys and no accidental intermediates.
8. **Run real local Dagster integration under coordinator lease.** Request heavy-test/materialization lease before execution. Use own durable `DAGSTER_HOME`, local staging/published dirs, unset cloud bucket variables, inherited proxy/TLS and frozen worktree environment. Register shared dynamic publish partition via `PUBLISH_PARTITION_NAME` / `build_publish_partition_key` and any ingest-specific partition using the same `DagsterInstance` passed to materialization. Actually materialize approved source ingest/support assets → catalog → all formats → verification → promotion. Save exact head/commands/config, registered partitions, source captures/checksums, run IDs/status, event logs/check evaluations and complete terminal inventory. Assert actual full baseline rows/IDs/attributes/geometries/schema/coverage/quality plus published STAC/download provenance and lineage. Run blocked drift variant proving no promotion and unchanged accepted release; separately execute direct/local helper accepted and blocked paths. Unit mocks/startup alone do not satisfy this step.
9. **Validate and request independent exact-head review.** Run focused tests and required full suite, retaining unsuppressed errors (known absent sibling IaC file is an environment limitation). Report evidence in separate real accepted-baseline pilot, synthetic integration and unapproved-baseline categories. Missing real baseline remains blocked. Include measured resource limits and unfinished format/source cases; do not claim dataset ingestion acceptance until gates and pilot pass. No production deployment, merge, issue closure or controller activation.
