# Shared full-data verification and promotion design

Date: 2026-10-19. Status: **proposal, needs maintainer design decision**. Issue: #417. This document neither implements verification nor approves a source, baseline, schema or release. PR #418 research is not an accepted contract. The proposed agency-recovery requirements in PR #1 remain proposals; this design does not activate its controller.

## Problem and inspected integration points

Three independently evidenced comparisons are required: complete agency extraction to raw staging; transformation accounting from raw staging to actual terminal outputs; and those outputs against an independently accepted published HIFLD Next release. Availability, equal counts and a plausible sample cannot establish acceptance.

Inspection of this branch on 2026-10-19 found:

- `validation.py` is empty. `checks/common.py` instead compares staged dictionaries and totals to hard-coded `v20260214`, accepts extra columns, uses ±10%, and passes absent baselines or the baseline partition itself. `checks/__init__.py` does not declare blocking checks and quality failures use WARN.
- `catalog.py` already provides dictionary/quality structures, but `_summarize_geospatial_source` stops at `CATALOG_SAMPLE_FEATURE_LIMIT`. Its sample geometry metrics and inferred types are not full-data evidence. Missing CRS defaults to EPSG:4326 in this path; the verifier must report unknown CRS instead.
- `assets/catalog.py::publish_catalog` snapshots source metadata and summarizes staging. `assets/publish.py` generates formats in staging, then `_copy_version_files` promotes via `promotion.py::promote_immutable_objects`. `run_local_version_pipeline` calls those helpers directly without a comparison gate. `_copy_source_format_files`, metadata copying and `write_immutable_object` are additional destination-write paths to audit.
- `promotion.py` already preflights immutable copies and pins object snapshots. Preserve these guarantees; immutability alone does not establish data acceptance.
- `download.py::download_convert_and_stage` loops downloads, holds response bodies in memory and stages source formats. Its URL list is not a union builder or proof of API completeness. It is optional for complex pipelines and is outside the comparator's bounded-memory claim.
- `source_manifest.py` resolves dataset/file/version layers with replacement by field and snapshots authored metadata. Inventory fallback may attribute an archive URL and is not authoritative multi-input provenance. `catalog.py::generate_data_dictionary` copies selected metadata fields; `_copy_metadata_files` currently names only quality and dictionary files. Portolan catalog/release/workflow consumers need explicit roundtrip coverage.
- `ingest_registry.py` registers explicit agency assets. `supported_assets.py::_from_ingest_assets` takes `next(iter(asset_def.keys))`; multi-output assets would lose terminal keys. Keep raw/supporting assets in Definitions separately from explicit terminal publishable outputs.

## Bounded-memory alternatives

| Approach | Memory/disk and work | Dependencies and limitations |
| --- | --- | --- |
| SQLite indexed row store with streamed readers (recommended) | Fixed reader batch, bounded SQLite cache, one row/geometry at a time; O(input bytes + indexes + full diff/lineage sidecars) disk; O(N log N) indexing | Python stdlib SQLite plus existing Fiona/PyArrow/Shapely. Explicit typed binary key encoding avoids SQLite numeric coercion. Slower than columnar joins but few new mechanisms. |
| External merge sort of typed row streams | Fixed sorted runs and bounded fan-in merge; O(N) temporary bytes plus merge copies and diff sidecars; O(N log N) work | No new Python package, but sorting framing, restart, merge scheduling and portable spill handling require more custom code. Strong later option for throughput. |
| Polars lazy/streaming joins over partitioned Parquet | Batches plus spill/hash partitions; disk includes canonical Parquet and spilled joins | Uses installed Polars/PyArrow. Version-specific operators may materialize or retain large hash/group state. Must measure and enforce limits; lazy syntax alone is no bounded-memory proof. |

Start with SQLite as the smallest auditable extension, not a new service or generic ingestion framework. Store exact typed canonical values and compare payload bytes for retained keys, not hashes alone; hashes locate objects and bind evidence. Use bounded cursor iteration, no `fetchall`, global Python sets, whole GeoDataFrames or all-key arrays. Disk-backed grouping also handles high-cardinality coverage and duplicate detection. A single exceptionally large feature requires a per-feature size cap and an explicit blocked result rather than exceeding memory.

Proposed defaults for evaluation: 8 MiB reader batches, SQLite cache 64 MiB, 1 MiB example budget, total worker RSS budget 512 MiB, maximum feature 32 MiB; these are engineering budgets requiring measurement, not data-acceptance tolerances. Preflight declared available scratch and enforce a configurable hard scratch quota throughout, including extracted archives, indexes, journal, sidecars and output. No fixed disk multiplier guarantees safety: stop blocked on quota/ENOSPC and retain the durable failure report. Stream remote downloads to checksum-pinned local files, validate archive expansion budgets and close handles before cleanup. Existing conversion stages need their own resource measurements; this proposal does not make the entire pipeline bounded-memory by assertion.

## Proposed interfaces and persisted contracts

Implement reusable Python interfaces in `validation.py`, with immutable dataclasses and versioned JSON serializers:

```python
resolve_baseline(inventory_id, published_storage, approved_reference) -> BaselineReference
iter_records(object_ref, schema_contract, batch_bytes) -> Iterator[TypedRecord]
verify_extraction(inputs, extraction_receipts, scratch, limits) -> StageResult
verify_transform(raw_refs, terminal_refs, transform_contract, lineage_refs, scratch, limits) -> StageResult
compare_full_rows(baseline, candidate, contract, scratch, limits) -> ComparisonReport
verify_candidate(request, staging_storage, published_storage) -> ComparisonReport
require_verified_promotion(request, source_snapshots, destination) -> PromotionPermit
```

`BaselineReference` v1 contains inventory ID; explicit inventory/crosswalk/catalog mapping evidence; dataset/file/semantic version; catalog and data dictionary URLs/checksums; every data object/layer URL, SHA-256, byte length and immutable generation/version where supported; schema/criteria digest; accepted-release decision ID, maintainer and date. Fetch immutable objects, verify bytes before parsing and retain checksummed captures or immutable retrievable evidence. Never resolve a moving latest pointer during comparison, select a staging candidate as its own reference, or substitute a mirror for the accepted baseline. Missing, ambiguous, unapproved, unreadable or checksum-mismatched references block. An approved initial contract needs a separate maintainer bootstrap decision; it is not automatically a real historical baseline pilot.

The approved contract defines every output column's exact name/type/nullability/meaning/ID role; every input schema and mapping; stable/composite match key and continuity evidence; geometry/CRS; expected partition roster and geography/category domains; source identity; and dataset-specific change/quality criteria. Unknown criteria remain blocking. Preserve source unknown fields losslessly in raw staging and report drift before projection. New/unmapped suspected IDs require review. Preserve ID whitespace, leading zeros, integer widths beyond 2^53, exact decimals, Unicode and null-vs-empty distinctions. Do not trim, case-fold, stringify numbers, use binary floats for integer keys, regenerate row numbers or assume OBJECTID continuity. Composite encodings use type tags and length framing; keys are indexed BLOBs, not SQLite REAL/INTEGER affinity. Duplicate and null keys fail before keyed comparison; if no defensible key exists, matching is unresolved.

Geometry comparison defaults to exact canonical coordinate/value comparison in a declared CRS with null/empty/type/validity distinctions; canonicalization is versioned and tested. Do not silently repair, round, reproject or infer CRS. Any semantic equality, reprojection or coordinate tolerance requires a dataset-specific reviewed rule, with raw differences still reported. Compare all attributes and geometries on all retained IDs. Check every promotable data representation against its declared contract: GeoPackage/GeoParquet and source archives must not lose fields or precision. Shapefile limitations need explicit format decisions, never silent truncation. PMTiles are a derived visualization: test source feature lineage and approved zoom/generalization/coverage rules, not false row equality to tiles. A format without a verifiable approved rule cannot be promoted.

## Extraction and transformation evidence

Each input/partition receipt includes stable identity, source snapshot/release, safe request/filter parameters, expected count and complete expected typed IDs where available, actual count/IDs, page boundaries, transfer-limit flags, retries, duplicates/null IDs, schema, checksum and capture references. ArcGIS HTTP 200 JSON errors fail. Reconcile count queries and every returned ID, detect repeated/skipped pages, transfer truncation, server caps and concurrent upstream mutation. Capture before/after revision or use a consistent snapshot; inconsistent extraction retries or blocks. Checksums alone cannot prove upstream completeness.

`TransformContract` describes a DAG of named steps and approved parameters, with receipts independently recomputed from retained inputs/outputs rather than trusted producer counters:

- Union/concatenation: exact expected partition roster, per-partition counts/full key sets, missing/overlapping partitions and duplicate policy. Verify every terminal branch and reject unregistered outputs.
- Join: declared 1:1/1:N/N:1 cardinality, full matched/unmatched key sets per side, multiplication counts and approved disposition of unmatched rows.
- Filter: exact predicate/version and complete excluded ID set with reasons; partition/coverage effects must be approved.
- Deduplication: full duplicate groups, representative selection, preserved source IDs and mapping of every discarded row.
- Aggregation/split: declared grain/group key, all contributing source IDs, group totals/conservation invariants and one-to-many lineage; grain or published-identity change remains a compatibility decision.
- Geometry/schema derivation: approved mappings and reprojection/normalization parameters, independently validated values, geometries and coverage.

A versioned row or partition lineage sidecar maps existing accepted output keys to `(input_id, partition_id, typed_source_key, step_id)`; aggregation supports many-to-one and split supports one-to-many. No arbitrary provenance columns enter the main table. Reconcile every raw row to a terminal lineage edge or an approved exclusion, and every terminal row to source contributions. This supports different raw/output counts without permitting unexplained losses.

## Reports and decision policy

Write `metadata/baseline_comparison.json` v1 and `.md` even on failure. Root fields: `schema_version`, `report_id`, `status` (`pass`, `blocked`, `breaking_change`, `fail`), `reason_codes`, dataset/file/candidate version, immutable `baseline`, candidate object inventory/checksums, contract/criteria/approval digests, verifier code commit and reader versions, run ID/command/timestamps, limits/observed peak RSS/scratch, `extraction`, `transformation`, `schema`, `ids`, `attributes`, `geometry`, `coverage`, `quality`, `provenance`, and evidence sidecars. Every stage includes status, full population denominators, violations, evidence and evaluated rule IDs. Interrupted/incomplete comparison never passes.

`ids` records baseline/candidate counts, unique/null/duplicate keys, retained/added/removed totals and checksummed full typed-key sidecars. `attributes` records per-field changed counts on retained rows and complete diff sidecars; bounded examples are illustrative only. `schema` reports additions/removals/renames/type/nullability/meaning/ID/CRS drift. `coverage` includes per-geography/category counts and missingness for both releases, missing/added buckets and extents (not extents alone). `quality` covers full null/empty/invalid geometry, coordinate range, duplicate rows/keys, required nulls, domains and source-date distributions. Bind all sidecars by schema, checksum, length and row count; no truncated JSON lists masquerade as complete sets.

Dataset-specific accepted criteria may allow evidenced producer additions/removals/value updates. They must reference release evidence and explicitly assessed ID, geography, category and quality effects. No universal percentage, sample pass, automatic baseline reset or self-approval. Missing evidence blocks; unapproved source/schema/ID/grain/coverage change routes to Potential breaking change and a maintainer decision. A legitimate update decision records before/after, impact, mapping/migration/versioning, approving maintainer, exact reviewed code and candidate/report/contract digests. Later byte or code changes invalidate it. Preserve previous baseline identity/history; accepting a new release is a separate controlled reference update after successful verification and release, never a comparator side effect.

## Blocking publication and provenance

Use two gates: blocking ERROR Dagster checks for extraction/schema/baseline/quality/provenance, and the same fail-closed shared function at every publish boundary. Catalog computes an initial report; generated terminal formats must be validated before a final promotion report is issued. Add an explicit final verification asset depending on catalog and all required generated formats, and make promotion depend on it; graph tests prove checks run before writes. Publish-only selections and direct helper invocation must still gate.

`PromotionPermit` is an internal validated result, not a caller-supplied boolean or serialized token accepted on trust. It binds exact dataset/file/version, destination, complete data+metadata object inventory/snapshots/checksums, baseline/contract/decision/verifier digests and final passing report. At boundary reload trusted approvals and check every current object against it; stale/missing/forged reports, added shards, replaced bytes and changed baseline/criteria block. Reuse storage conditional-copy snapshots to close the check/copy race. Cover `_copy_version_files`, `_copy_source_format_files`, `_copy_metadata_files`, public `publish_version`, `run_local_version_pipeline`, Portolan workflow and lower-level promotion/write paths reachable for releases. Generic storage copies remain primitives; release destinations must only be reachable through the checked promotion API, including direct/local calls. Audit call sites and expose no release bypass/overwrite flag.

Preflight the whole batch before first published write. Copy to an immutable unpublished release prefix where needed, then expose catalog/latest/discovery pointers only after complete inventory and metadata checks succeed, using conditional updates. Cross-object storage writes are not transactions: failure can leave unreferenced partial candidate objects; never list these as accepted releases. Preserve last accepted pointer and objects and all staged failure evidence; retry is idempotent. No production writes are authorized by this proposal.

Extend existing `source_manifest.py` to a versioned multi-input manifest: output dataset/file/version; processor HIFLD Next; `inputs[]` keyed by stable input ID, producer/title, actual publisher/account/host, role (`producer_publication`, `official_distributor`, `mirror`, `archive`, `unresolved`), official canonical/landing and actual retrieval URLs, delegation/lineage evidence, release/observation date or explicit unknown reason, retrieval timestamp, file/layer/service identity, checksum/length, geography/time coverage, rights/license/attribution; transformations/parameters/code commit; lineage sidecar descriptors. Redact credentials and signed URL secrets. Unknown release dates remain unknown; portal edits/fetch times never become producer release dates. Unresolved authority or misleading dates/rights block under criteria.

Resolve defaults separately from the version-pinned manifest; merge inputs by explicit identity with conflict detection rather than replace an entire list. Snapshot immutable version metadata. Propagate complete manifest, comparison report, readable summary and lineage sidecars through dictionary/catalog asset metadata, metadata copy, Portolan catalog/STAC generation and downloadable metadata assets. STAC must show readable agency attribution and official links, all contributors and role labels, HIFLD Next's processing/distribution role, plus stable links/checksums for downloadable manifest/report/lineage. Inventory defaults or research `source.json` alone cannot pass. Test reloading published STAC and downloads and resolving every manifest input and sidecar without loss.

## Verification and rollout acceptance

Implementation tests must include missing/unapproved/unmatched/changed baseline; same row count with different IDs; one missing geography hidden by additions elsewhere; extra/renamed fields, ID removal, whitespace/leading-zero/large-integer/decimal loss; null/duplicate keys; late-file geometry/domain/null regression beyond sample limit; truncated conversion and missing GeoParquet shards; inconsistent API pages/counts/errors; every transformation's accounting and lineage; evidenced legitimate update allowed only by exact approval; stale/forged reports and post-report mutations; all direct/local and low-level release helper bypasses; failed partial promotion preserving prior release; source manifest conflict, multi-input STAC/download roundtrip and secret omission. Include multi-output terminal registration and supporting-asset exclusion.

Run a bounded-memory subprocess test with growing synthetic inputs larger than the RSS budget and high-cardinality groups/keys; assert full exact differences, measured peak RSS below limit and linear disk growth within configured quota, including duplicate/oversized geometry cases, quota exhaustion and interruption. Synthetic tests demonstrate mechanics, never a real-baseline acceptance claim.

After design approval, obtain a coordinator heavy-test lease and a maintainer-approved pilot dataset/reference/contract. Run actual local Dagster materialization with its durable `DagsterInstance`/`DAGSTER_HOME`, local storage only and the dynamic partition registered (`PUBLISH_PARTITION_NAME` and `build_publish_partition_key` for shared publish; register ingest-specific definitions too). Run actual source-specific ingest/supporting assets and catalog → formats → final verification → promotion, not mocked `materialize` or helper-only tests. Record exact code head, safe command/config, partition registration, input captures/checksums, run IDs, event logs, final run status and check evaluations. Assert actual terminal output inventory, full baseline rows/IDs/attributes/geometries, schema/quality/coverage, manifest/lineage and published STAC/download provenance. Repeat with a drifted candidate: failed blocking checks, no promotion/pointer update and unchanged accepted release. Independently exercise direct/local pipeline and promotion helpers, both accepted and blocked, to prove the graph is not the only enforcement.

Label evidence separately: **real accepted-baseline pilot**, **synthetic integration**, **unapproved-baseline experiment**. Only the first satisfies the pilot requirement. If no accepted reference is available, report pilot blocked; do not materialize an unapproved source or invent acceptance. Readiness startup is not materialization correctness. Full suite remains required when implementation occurs; known missing sibling `hifld-next-iac/environments/prod/dagster.tf` is an unsuppressed environment limitation.
