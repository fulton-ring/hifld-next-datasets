## What changed

Migrates two #1069 NHD/3DHP modules to the shared capture-completeness
machinery (`capture_completeness.validate_capture_witness`, dynamic count plus
ID roster, before/after witnesses), following the
`nhd_hydrolocation_sink_spring_waterbody_outlet` pattern (#1171):

- `nhd-hydrolocation-reach-code-external-connection` (3DHP_all layer 40,
  point features, `featuretype=9` "External Connection"):
  - Removed the static population pins (`EXPECTED_COUNT=25`, ID/record/geometry
    SHA256, geometry count pins, observed bounds, featuretype distribution).
  - Completeness now requires the verified before/after count and ID-roster
    witness, `feature_count == source_reported_count`, the schema pin, native
    ID uniqueness and the transport integrity checks.
  - Replaced the contiguous OBJECTID roster assumption (`range`-based segment
    gap planning) with the actual roster slice, so a non-contiguous ID
    population is captured correctly instead of being misplanned.
  - Added the approved-baseline drift asset check: with no approved baseline
    the check reports `skipped_no_approved_baseline` and warns on any captured
    population that differs from an approved baseline; releases stay unapproved.
- `nhd-area-large-scale` (3DHP_all layer 60, polygon features,
  `featuretype<>3` population):
  - Removed the static pin (`EXPECTED_COUNT=95423`).
  - Completeness is scoped to the `featuretype<>3` population by the witness
    (the unfiltered layer 60 is ~7.16M features; `featuretype=3` is ~7.06M),
    so the count and roster witnesses are the population contract.

Out of scope by design and untouched (verified with an empty
`git diff origin/main..HEAD` on these paths): the #1094 family modules
(`nhd_catchment`, `nhd_flowline`, `nhd_hydrolocation_htdcco`, `uscg_sectors`),
the census modules (`local_roads_census`, `secondary_roads_census`) and the
shared `sources/arcgis_layer.py`.
